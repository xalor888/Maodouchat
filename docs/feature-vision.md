# Maodouchat 功能与特性全景（对标 TG / 微信 / QQ）

**更新日期**：2026-08-01
**定位**：比 TG / 微信 / QQ **更安全、更轻量、更智能、更好用**。
**口径**：本文件是「产品愿景 + 功能总清单 + 现状盘点」。标注 `已有` = 代码已存在（见 `feature-inventory.md` 细节）；`本期建设` = 交给本次各区块 Agent 开发（见 `docs/blocks-plan.md` 与 `docs/agent-prompts/`）；`暂不做` = 明确不做。

> 规模基线：Release APK 现 ~19.7MB（旧包，含已废弃的 9.86MB WebRTC `.so`）；用当前排除规则重建后 ≈ 9~10MB。目标 **≤10MB**，见 B1 区块。

---

## 0. 核心卖点一句话

- **更安全**：Signal 系 E2EE、密聊防泄漏栈（防截屏/盲水印/侧信道封堵）、SQLCipher 本地加密、可离线纯本地搜索。
- **更轻量**：APK ≤10MB、WebRTC 原生库按需下载、R8 全模式、资源收缩。
- **更智能**：端上 AI 改写/摘要/语义搜索/任务提取/图片理解/语音转写、智能提醒。
- **更好用**：沉浸动效、密聊/群玩法、媒体中心、系统级来电、跨设备多端同步。

## 3. 明确暂不做（保持轻量）

- iOS / 桌面客户端
- 支付 / 红包 / 电商小程序
- 大群 SFU 会议（保持 mesh ≤6）
- 端侧大模型 embedding 进包（明确禁止）
- 国内厂商推送通道（仅 FCM）
- Sealed Sender 完整证书链（保持当前 flag + 客户端门控）
- 网页版客户端

## 4. 区块 ↔ 文件边界速查

> 冲突红线（所有 Agent 必须遵守）：
> 1. **禁止修改巨型文件**：`ChatDetailViewModel.kt`、`ChatDetailScreen.kt`、`ChatListScreen.kt`、`Routing.kt`、`GroupPlayPolicy.kt`（除非区块说明明确允许「末尾追加」）。
> 2. **服务端新路由**：新建独立 `server/.../plugins/<区块>Routing.kt`，在 `Application.kt` 的 `embeddedServer {}` 块**末尾追加一行**注册，不删除任何现有行。
> 3. **strings.xml**：只追加新 `<string>`，不改已有 name。
> 4. **不删除/重命名**任何现有文件、类、函数；新增类命名带区块前缀（如 `Poll*`、`AiProfile*`）。

详见 `docs/blocks-plan.md` 与 `docs/agent-prompts/*.md`。
